# Hydrology FTE Agent (HydroWatch Pro)

A prototype that automates a routine hydrology workflow: it reads river measurement data from CSV files, computes discharge, classifies flow as low, moderate or high, and writes a report. High-risk results can trigger an email alert, which is only sent after a human approves it.

Built for the Personal AI Employee Hackathon (2026). The project reached the Silver tier of the hackathon's tier system.

**Status:** prototype tested on sample data. It has not been validated against observed gauge records and should not be used for real flood warnings.

---

## Problem

Turning field measurements into discharge values and a written summary is repetitive work. This project tries to put those steps into one automated pipeline: drop a data file into a folder, and a report appears.

Pakistan is flood-prone, which is why the example data uses Pakistani rivers (Chenab, Indus, Ravi, Jhelum). The numbers in the examples are made up for testing and are not real measurements.

---

## What it does

1. Watches an inbox folder for new CSV files with river measurements.
2. Loads and validates the data with pandas.
3. Computes discharge with the continuity equation, Q = width × depth × velocity.
4. Classifies each river as low, moderate or high flow using fixed discharge thresholds (defined in `skills/analyze_flow_condition.py`).
5. Writes a markdown report with the calculation, the classification and suggested follow-up actions.
6. For high-risk results, drafts an email alert and waits for a human to approve it before sending (Gmail SMTP).
7. Optionally generates a LinkedIn post if API credentials are configured.

Additional inputs: a watcher for PDF weather bulletins and a Gmail watcher for CSV attachments. A Qwen model is used to decide which step runs next and to write the plain-language parts of the reports. Each run also writes a short plan file so the decisions can be reviewed.

---

## Assumptions and limitations

- Discharge is width × depth × velocity, which treats the channel as a rectangle. Real cross-sections are irregular, so values are approximate.
- Risk classes use fixed thresholds that are not specific to each river or to any official flood-stage standard.
- Inputs are one set of width, depth and velocity values per river. There is no time series, rating curve or gauge calibration.
- All results shown here come from sample files, not field data.
- The "what this means" text in reports is generated by an AI model and has not been reviewed by a hydrologist.
- Runs on Windows only (scheduling uses Windows Task Scheduler).
- Email and LinkedIn features need your own credentials.

## Tools

- Python (tested on 3.13), pandas
- Qwen Code CLI (`@qwen-code/qwen-code`), used for AI-assisted development and as the decision and writing component at runtime
- File watchers for CSV, PDF and approval folders, plus a Gmail watcher
- Gmail SMTP and an MCP email server for alerts
- LinkedIn API (optional)
- Windows Task Scheduler for timed runs
- Markdown vault (Obsidian-style folders) for inbox, reports and dashboard

The project was developed with an AI coding assistant (Qwen Code CLI).

## Architecture

```
Watchers (CSV / PDF / Gmail / approval)
        |
   Orchestrator  <-->  Qwen model (next-step decisions, report text)
        |
     Skills: ingest_data, compute_discharge, analyze_risk,
             generate_report, create_plan, send_alert, post_linkedin
        |
   Outputs: reports in Hydrology-Vault/Done/, alert emails (after approval),
            dashboard in Hydrology-Vault/Dashboard.md
```

## How to run

Requirements: Windows 10/11, Python 3.8+, Qwen CLI (`npm install -g @qwen-code/qwen-code`), and a Gmail account if you want email alerts.

```
git clone https://github.com/Zainab07-mm/Hydrology-FTE-Agent.git
cd Hydrology-FTE-Agent
pip install -r requirements.txt
copy .env.example .env
```

Edit `.env` with your own values:

```
GMAIL_ADDRESS=your_email@gmail.com
GMAIL_APP_PASSWORD=your_16_char_app_password
ALERT_RECIPIENT=recipient@example.com

# Optional
LINKEDIN_ACCESS_TOKEN=your_token_here
LINKEDIN_PERSON_ID=your_profile_id
```

Start the agent:

```
python main.py             # main loop
python main.py --watcher   # run all watchers
python main.py --linkedin  # generate a LinkedIn post manually
```

### Try it with sample data

Save this as a CSV file in `Hydrology-Vault/Inbox/` (values are invented for testing):

```
River,Width_m,Depth_m,Velocity_mps
Chenab,35,2.5,1.8
Indus,55,3.5,2.2
Ravi,28,1.8,1.4
Jhelum,40,2.8,1.6
```

The agent detects the file, computes discharge, classifies risk and writes a report to `Done/`. If any river is high risk, it prepares an alert email and waits for approval.

### Sample report output (sample data)

```
River: Chenab
Calculation: Q = 35 m x 2.5 m x 1.8 m/s = 157.5 m3/s
Condition: High
```

## Future work

- Replace manual CSV drops with a live data source such as the Pakistan Meteorological Department.
- Validate discharge and risk classes against observed gauge data.
- Use cross-section geometry instead of a rectangular assumption.
- Set thresholds per river from published flood-stage values.
- Add a web dashboard and cloud deployment.
- Explore flood-extent mapping with satellite data and discharge forecasting with machine learning.
